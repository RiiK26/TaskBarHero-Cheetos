# Project: TaskBarHero-Cheetos

## 1. Project Overview & Architecture
An internal memory manipulation, feature modification, and offset management utility for *TaskBarHero*.
The project consists of two interacting components:
1. **Host Executable (`TBH-Cheetos.exe`):** A C++ Win32 application utilizing `ProcessMemory` (RPM/WPM) and ImGui + GLFW/OpenGL3 to provide an interactive cheat control dashboard.
2. **Injected Hooking DLL (`speedhack.dll`):** A lightweight shared library injected into the game process via MinHook to modify engine time APIs.

### Target Game Details
* **Name:** *TaskBarHero* (Steam AppID: `3678970`)
* **Engine:** Unity 6000.0.72f1, x86_64 IL2CPP
* **Backend:** The Backend (BACKND / 뒤끝 - `thebackend.io` BaaS)
* **Anti-Cheat:** CodeStage Anti-Cheat Toolkit (ACTk) + custom in-game anti-abuse guards

## 4. Codebase Architecture Map

### `src/core/` — Memory Management & IL2CPP Primitives
* [ProcessMemory.h](../src/core/ProcessMemory.h): Win32 process attachment, safe RPM/WPM wrappers, virtual memory region queries (`VirtualQueryEx`), module base address and size lookup.
* [AOBScanner.h](../src/core/AOBScanner.h): High-performance parallelized memory scanning engine (`ScanModulePattern`, `ScanStrided`, `ScanAligned`, `ScanObscuredLong`, `ScanObscuredDouble`, `Scan`). Uses 1 MB chunk pools across worker threads.
* [Signatures.h](../src/core/Signatures.h): Centralized C++ registry of all 22  AOB signatures and fallback RVAs generated from `config.json` (AntiCheat detectors, `Time.set_timeScale`, `StageManager`, `SaveManager`, and `PlayerSaveData`).
* [Il2CppOffsets.h](../src/core/Il2CppOffsets.h): Centralized single source of truth for ALL struct member offsets and IL2CPP container structures (`Il2CppListOffsets`, `Il2CppArrayOffsets`, `Il2CppDictOffsets`, `Il2CppStringOffsets`).
* [Il2CppListReader.h](../src/core/Il2CppListReader.h) & [Il2CppDictionaryReader.h](../src/core/Il2CppDictionaryReader.h): Generic IL2CPP collection readers consuming centralized container layout constants from `Il2CppOffsets.h`.
* [Il2CppStatDictionary.h](../src/core/Il2CppStatDictionary.h): Reads and parses `Dictionary<StatType, float>` for hero attributes using centralized `Il2CppDictOffsets` and `Il2CppArrayOffsets`.
* [ObscuredTypes.h](../src/core/ObscuredTypes.h): Decryption and serialization helpers for ACTk types (`ObscuredInt`, `ObscuredFloat`, `ObscuredDouble`, `ObscuredLong`, `ObscuredString`).

### `src/features/` — Game Modifications
* [AntiCheatBypass.h](../src/features/AntiCheatBypass.h): Multi-tiered bypass engine neutralizing detector entrypoints in `GameAssembly.dll` using `RET (0xC3)` or `xor eax, eax; ret (31 C0 C3)`. Dynamically resolves targets via  AOB patterns in `Signatures.h` with RVA fallback.
* [ExpMultiplier.h](../src/features/ExpMultiplier.h) / [.cpp](../src/features/ExpMultiplier.cpp): Applies EXP multiplier to heroes, utilizing cached hero addresses.
* [GodMode.h](../src/features/GodMode.h): Overwrites stat values (Damage, HP, Crit Chance, Attack Speed, Movement Speed, Range) across all heroes.
* [RuneUnlocker.h](../src/features/RuneUnlocker.h) / [.cpp](../src/features/RuneUnlocker.cpp): Unlocks and maxes rune levels based on `PlayerDataFinder` scan results and `RuneSaveDataOffsets`.
* [speedhack.cpp](../src/features/speedhack.cpp): Standalone DLL injected into the game. Hooks `QueryPerformanceCounter`, `timeGetTime`, and `GetTickCount` in `UnityPlayer.dll` to scale engine delta time.

### `src/scanner/` — Entity Finding & Tracing
* [HeroFinder.h](../src/scanner/HeroFinder.h): Discovers all 6 heroes in memory via batched pointer scanning. Features address caching and validity verification.
* [PlayerDataFinder.h](../src/scanner/PlayerDataFinder.h) / [.cpp](../src/scanner/PlayerDataFinder.cpp): Locates `PlayerSaveData` by upward pointer tracing from candidate heroes and parses active rune dictionaries using centralized `Il2CppDictOffsets`.

### `src/ui/` — User Interface
* [CheetosGUI.h](../src/ui/CheetosGUI.h) / [.cpp](../src/ui/CheetosGUI.cpp): Renders the ImGui interface, handles speedhack injection, and coordinates feature activations. Dynamically isolates `imgui.ini` location adjacent to the executable.

## 5. Reverse Engineering Boundaries & Core Conventions

1. **Centralized Signatures vs Centralized Struct Offsets:**
   * **Executable Methods & Hooks:** All function signatures and detector entrypoints are centralized in [config.json](file://config.json) / [Signatures.h](../src/core/Signatures.h) using  AOB signatures with masked RIP displacements and branch targets (22 targets).
   * **Data Structures & Field Offsets:** All class field offsets and IL2CPP container structures are strictly centralized in [Il2CppOffsets.h](../src/core/Il2CppOffsets.h) and synchronized with `config.json` via [validate_offsets.py](file://resources/tools/validate_offsets.py).
   * **No Decentralized Offsets:** Feature readers (`Il2CppStatDictionary.h`, `Il2CppDictionaryReader.h`, `Il2CppListReader.h`) must NEVER declare local duplicate offsets; all container and field offsets route through `Il2CppOffsets.h`.
2. **Rune Dictionary Scanning Invariant:**
   * In [PlayerDataFinder.cpp](../src/scanner/PlayerDataFinder.cpp), keep the rune count range check:
     ```cpp
     // Total runes history during update: 197 -> 241 -> 248 -> 253
     if (val >= 248 && val <= 260)
     ```
   * Preserve the strict 5-entry inner dictionary verification (`validInnerCount == 5`). Never loosen this validation or drop key `0` during dictionary parsing; doing so allows false-positive candidate dictionaries to corrupt rune data.
3. **Speedhack Scope Boundary (CRITICAL):**
   * [speedhack.cpp](../src/features/speedhack.cpp) must **ONLY** intercept calls from `UnityPlayer.dll`:
     ```cpp
     inline bool IsTargetCaller(uintptr_t caller)
     {
       return (caller >= g_UnityPlayerBase && caller < g_UnityPlayerEnd);
     }
     ```
   * **NEVER hook calls from `GameAssembly.dll`.** Managed C# code contains backend HTTP networking (`HttpClient`), BACKND JWT token managers, and retry loops.
   * **NEVER hook calendar clock APIs (`GetSystemTimeAsFileTime`, `GetSystemTimePreciseAsFileTime`).** Hooking them fast-forwards `DateTime.UtcNow`, causing BACKND 24-hour access tokens to expire prematurely.
4. **Hero Address Caching:**
   * Always prefer cached addresses via `HeroFinder::FindAll(false)` for God Mode and EXP Multiplier operations to avoid redundant full-memory scans.
5. **Use `ProcessMemory` Over Raw Win32:**
   * Avoid calling raw `ReadProcessMemory` / `WriteProcessMemory` directly in feature logic; use the typed wrappers in `ProcessMemory.h`.
6. **ImGui Runtime Configuration Isolation:**
   * [CheetosGUI.cpp](../src/ui/CheetosGUI.cpp) dynamically resolves the module directory via `GetModuleFileNameA` and explicitly sets `io.IniFilename = s_iniPath.c_str()`.
   * `imgui.ini` is strictly stored alongside `TBH-Cheetos.exe` and `speedhack.dll` in `build/`. It must never be created or stored in the repository root.
   * Launcher scripts (`scripts/launch_linux.sh`, `scripts/launch.bat`) must `cd` into the executable's directory prior to running Wine or the binary.
